# 全 A 股分红查询页面设计

## 目标

在现有 Tauri 桌面应用中新增独立的“分红查询”页面，支持按东方财富行业或股票代码/名称查询全 A 股分红数据。页面同时提供横向筛选表格和单股分红历史详情，并明确展示数据来源、采集时间与方案实施状态。

第一版使用实时查询，不建立持久化缓存。用户必须先选择行业或输入股票，再主动触发查询，避免打开页面时逐只请求全市场股票。

## 范围

### 包含

- 东方财富行业列表及行业成分股查询。
- 按股票代码或名称搜索 A 股。
- 当前行情与历次现金分红方案查询。
- 最近完整年度和近 12 个月两种股息率口径。
- 行业结果的筛选、排序和查询进度。
- 单股历年分红详情与公告追溯入口。
- 数据来源、行情时间和分红采集时间展示。
- 单只股票失败与整体请求失败的独立处理。

### 不包含

- 港股、美股或基金分红。
- 申万行业分类。
- 后台全量同步或 SQLite 持久化缓存。
- 交易所或巨潮资讯双源自动校验。
- 自动投资建议或收益预测。

## 页面入口

在应用侧栏增加 `/dividends` 路由，菜单名称为“分红查询”，与现有“选股”页面并列。现有“选股”继续负责固定的央企高股息与 BOLL 策略，不承载通用分红查询状态。

## 页面布局

页面沿用现有 Ant Design 组件、主题变量和紧凑型表格视觉。

### 查询区

- 使用分段控件切换“按行业”和“按股票”。
- 按行业时展示可搜索的东方财富行业下拉框。
- 按股票时展示支持代码或名称的搜索输入框和候选列表。
- “查询”按钮是唯一的数据请求触发入口。
- 未选择有效条件时禁用查询按钮。
- 页面初次打开不自动发起全市场查询。

### 口径与筛选区

- 口径分段控件包含“最近完整年度”和“近 12 个月”。
- 两种口径数据始终保留在结果中，切换只改变默认排序与重点展示。
- 支持股息率区间和方案状态筛选。
- 支持按股息率、每股现金分红和股票名称排序。

### 结果表格

表格字段包括：

- 股票名称、代码和交易所。
- 东方财富行业。
- 当前价和行情时间。
- 最近完整年度每股现金分红及股息率。
- 最近完整年度已实施金额和待实施金额。
- 近 12 个月已实施每股现金分红及股息率。
- 最近分红方案状态与除息日。
- 分红数据采集时间。
- 查看详情操作。

行业批量查询时显示“已完成 X/Y”。单只股票查询失败时保留结果位置并展示简短失败原因，不让整批查询失败。整体接口失败时显示页面级错误提示和重试按钮。

### 单股详情

点击股票行或详情操作打开右侧抽屉。抽屉展示：

- 股票名称、代码、行业和当前行情。
- 两种股息率摘要。
- 历次分红的报告期、原始方案文本、每股现金分红、统一状态、股权登记日、除息日和公告入口。
- 数据来源和采集时间。

公告入口优先使用接口提供的稳定公告标识或原文链接。无法构造稳定原文直链时，提供包含股票代码、公告日期和方案关键词的东方财富公告检索入口，并标记为“公告检索”。

## 架构

### 前端

新增独立 React 页面和类型定义，通过 `src/api/index.ts` 调用 Tauri 命令。前端职责包括：

- 管理查询模式、条件、加载进度、筛选、排序和详情抽屉。
- 呈现标准化后的领域数据。
- 区分整批错误与单股错误。
- 不直接请求东方财富接口，也不自行解析第三方 JSON。

### Tauri 命令

新增分红查询命令，提供清晰的数据边界：

- 获取东方财富行业列表。
- 获取指定行业成分股。
- 按代码或名称搜索股票。
- 查询单股分红详情。
- 查询指定行业的分红摘要。

行业查询由后端编排：先获取成分股，再以受限并发查询分红和批量行情，逐项产生成功或失败结果。首版不把查询结果写入 SQLite。

### Rust 服务

新增独立 `dividend_query` 服务。复用现有东方财富 HTTP 获取能力和经过测试的分红/行情解析逻辑，但不依赖现有固定选股策略、央企分类或 BOLL 计算。

服务内部边界：

- `industry/universe`：构造并解析行业及成分股请求。
- `dividend`：获取分红历史并统一状态和每股口径。
- `quote`：批量获取当前行情。
- `orchestration`：控制并发、聚合结果和记录部分失败。

如果现有解析器缺少本页面所需字段，应扩展共享的原始数据模型和解析结果，而不是复制一套相同的第三方 JSON 解析代码。

## 数据口径

### 分红记录

每条记录保留以下原始或可追溯字段：

- 报告期。
- 原始方案文本。
- 第三方返回的实施进度。
- 每 10 股现金金额和归一化后的每股现金金额。
- 股权登记日和除息日。
- 公告日期、公告标识或公告入口信息。

统一状态至少包含：`proposal`、`approved`、`implemented` 和 `unknown`。界面分别显示“预案”“已通过”“已实施”“状态未知”。未知状态不计入已实施统计。

### 最近完整年度

“最近完整年度”指查询日之前已经结束、且存在分红披露记录的最近会计年度。该口径同时返回：

- 该年度已实施每股现金金额。
- 该年度待实施每股现金金额。
- 该年度全部披露现金方案金额。
- 以全部披露现金方案金额除以当前价计算的披露口径股息率。
- 以已实施金额除以当前价计算的已实施口径股息率。

列表主列默认展示披露口径，并用状态拆分避免把待实施金额误认为已到账。

### 近 12 个月

以查询日期向前推 12 个月形成区间，按除息日纳入记录，仅统计状态为“已实施”的现金分红。日期边界采用闭区间，并在实现中使用日历月回退，避免固定 365 天导致闰年偏差。

### 股息率

股息率等于对应口径的每股现金金额除以当前价。当前价不存在或不为正数时股息率返回空值，界面显示 `--`，不使用历史价格替代。

所有股息率必须带口径标签，不直接复用第三方接口中语义可能不同的股息率字段。

## 数据来源与真实性提示

页面明确标注“分红与行情数据来源：东方财富公开数据接口”，并分别展示行情观察时间和分红数据获取时间。

东方财富属于第三方聚合源，不表述为交易所官方数据。公告入口用于人工追溯；若入口仅为检索页，界面必须明确标注，不能显示为“公告原文”。

## 错误处理

- 行业列表失败：查询控件显示错误和重试操作。
- 股票搜索失败：保留输入内容并显示局部错误。
- 行业成分股失败：终止该次查询并显示页面级错误。
- 行情失败：仍展示分红数据，现价和股息率显示 `--`。
- 单股分红失败：保留该股票及失败原因，其他股票继续完成。
- 返回字段缺失或格式异常：解析器返回明确错误，不静默转换为零。
- 第三方限流或超时：使用受限并发和有限次数重试；不无限重试。

## 测试

### Rust 单元测试

- 行业列表和成分股 JSON 解析。
- 分红方案文本、金额、日期、公告字段和状态归一化。
- 最近完整年度选择及已实施/待实施拆分。
- 近 12 个月的月历边界、闰年和除息日统计。
- 当前价缺失或为零时不计算股息率。
- 批量查询中部分失败仍返回其他结果。
- 并发限制和有限重试行为。

### 前端测试

- 未选择条件时不能查询。
- 查询模式切换清理不适用条件。
- 两种口径切换改变重点列和默认排序。
- 股息率区间、状态筛选和排序。
- 进度、空状态、整体错误和单股错误展示。
- 详情抽屉展示历年记录及正确的公告入口标签。

常规自动化测试使用固定 JSON 样本和模拟 Tauri 响应，不依赖实时第三方网络。可另设显式执行的 live API 测试用于人工验证接口兼容性。

## 验收标准

- 用户可选择任一东方财富行业并主动查询其 A 股成分股分红摘要。
- 用户可通过代码或名称找到 A 股并查看历年分红详情。
- 表格同时展示最近完整年度和近 12 个月两种股息率，定义与实施状态清晰。
- 单只股票请求失败不会中断整批行业查询。
- 所有数据都能看到来源和采集时间，公告原文与公告检索入口不会混淆。
- 页面首次打开不进行全 A 股分红请求，也不建立持久化缓存。
