# 全 A 股分红查询页面设计

## 目标

在现有 Tauri 桌面应用中新增独立的“分红查询”页面，支持按东方财富行业或股票代码/名称查询全 A 股分红数据。页面同时提供横向筛选表格和单股分红历史详情，并明确展示数据来源、采集时间与方案实施状态。

第一版使用实时查询，不建立持久化缓存。用户必须先选择行业或输入股票，再主动触发查询，避免打开页面时逐只请求全市场股票。

## 范围

### 包含

- 东方财富行业列表及行业成分股查询。
- 按股票代码或名称搜索 A 股。
- 当前行情与历次现金分红方案查询。
- 最近完整年度和近 12 个月两种股息率口径。
- 行业结果的筛选、排序和查询进度。
- 单股历年分红详情与公告追溯入口。
- 数据来源、行情时间和分红采集时间展示。
- 单只股票失败与整体请求失败的独立处理。

### 不包含

- 港股、美股或基金分红。
- 申万行业分类。
- 后台全量同步或 SQLite 持久化缓存。
- 交易所或巨潮资讯双源自动校验。
- 自动投资建议或收益预测。

## 页面入口

在应用侧栏增加 `/dividends` 路由，菜单名称为“分红查询”，与现有“选股”页面并列。现有“选股”继续负责固定的央企高股息与 BOLL 策略，不承载通用分红查询状态。

## 页面布局

页面沿用现有 Ant Design 组件、主题变量和紧凑型表格视觉。

### 查询区

- 使用分段控件切换“按行业”和“按股票”。
- 按行业时展示可搜索的东方财富行业下拉框。
- 按股票时展示支持代码或名称的搜索输入框和候选列表。
- “查询”按钮是唯一触发分红结果查询的入口。行业选项属于页面元数据，可在页面打开时加载；股票候选在用户输入至少 2 个字符后以 300ms 防抖搜索，不获取分红或行情。
- 未选择有效条件时禁用查询按钮。
- 页面初次打开不自动发起全市场查询。

“全 A 股”包含上交所、深交所和北交所的普通人民币股票，包括主板、科创板、创业板和北交所股票；不包含 B 股、基金、债券、可转债、存托凭证和已退市证券。代码在后端规范化为六位数字加 `SH`、`SZ` 或 `BJ` 交易所。同名候选必须同时展示代码和交易所。

### 口径与筛选区

- 口径分段控件包含“最近完整年度”和“近 12 个月”。
- 两种口径数据始终保留在结果中，切换只改变默认排序与重点展示。
- 支持股息率区间和聚合方案状态筛选。聚合状态取最近一条有效现金方案的统一状态。
- 支持按股息率、每股现金分红和股票名称排序。

口径切换到“最近完整年度”时，默认按该年度披露口径股息率降序；切换到“近 12 个月”时，默认按近 12 个月已实施股息率降序。用户手动选择其他排序后，切换口径会重置为对应默认排序。重点列使用现有表格强调色，不隐藏另一口径。

### 结果表格

表格字段包括：

- 股票名称、代码和交易所。
- 东方财富行业。
- 当前价和行情时间。
- 最近完整年度每股现金分红及股息率。
- 最近完整年度已实施金额和待实施金额。
- 近 12 个月已实施每股现金分红及股息率。
- 最近分红方案状态与除息日。
- 分红数据采集时间。
- 查看详情操作。

行业批量查询时显示“已完成 X/Y”。单只股票查询失败时保留结果位置并展示简短失败原因，不让整批查询失败。整体接口失败时显示页面级错误提示和重试按钮。用户发起新查询、离开页面或关闭详情所属查询时取消旧查询；前端只接收当前查询 ID 的事件，旧事件不得覆盖新结果。

### 单股详情

点击股票行或详情操作打开右侧抽屉。抽屉展示：

- 股票名称、代码、行业和当前行情。
- 两种股息率摘要。
- 历次分红的报告期、原始方案文本、每股现金分红、统一状态、股权登记日、除息日和公告入口。
- 数据来源和采集时间。

公告入口由后端返回判别类型 `original`、`search` 或 `none`。只有经 URL 解析并确认属于 `cninfo.com.cn`、`sse.com.cn`、`szse.cn` 或 `bse.cn` 允许域名的直接公告详情链接才可标记为 `original`。其他第三方链接不得显示为公告原文。无法确认原文时，提供包含股票代码、公告日期和方案关键词的东方财富公告检索入口并标记为 `search`；无法构造时返回 `none`。

## 架构

### 前端

新增独立 React 页面和类型定义，通过 `src/api/index.ts` 调用 Tauri 命令。前端职责包括：

- 管理查询模式、条件、加载进度、筛选、排序和详情抽屉。
- 呈现标准化后的领域数据。
- 区分整批错误与单股错误。
- 不直接请求东方财富接口，也不自行解析第三方 JSON。

### Tauri 命令

新增分红查询命令，提供清晰的数据边界：

- 获取东方财富行业列表。
- 获取指定行业成分股。
- 按代码或名称搜索股票。
- 查询单股分红详情。
- 查询指定行业的分红摘要，并通过 Tauri channel 返回进度事件。
- 取消指定查询。

行业查询由后端编排：先获取成分股，再以受限并发查询分红和批量行情，通过带查询 ID 的 channel 逐项产生成功或失败结果。首版不把查询结果写入 SQLite。

命令与合同如下；Rust 使用可序列化 DTO，TypeScript 定义同构类型并添加固定样本序列化测试：

- `list_dividend_industries() -> Result<Vec<DividendIndustry>, CommandError>`
- `search_dividend_stocks(query: String) -> Result<Vec<DividendStockRef>, CommandError>`，最多返回 20 条。
- `start_dividend_query(input: DividendQueryInput, on_event: Channel<DividendQueryEvent>) -> Result<(), CommandError>`
- `cancel_dividend_query(query_id: String) -> Result<(), CommandError>`，重复取消视为成功。
- `get_dividend_stock_detail(stock: DividendStockRef) -> Result<DividendStockDetail, CommandError>`

`DividendQueryInput` 包含调用方生成的 `query_id`、查询模式，以及行业 ID 或规范化股票引用。无效的模式和条件组合在发起网络请求前返回验证错误。

`DividendQueryEvent` 是按 `type` 判别的联合类型：

- `started { query_id, total, started_at }`
- `item { query_id, completed, total, result }`
- `finished { query_id, completed, total, succeeded, failed, quote_observed_at, dividend_fetched_at }`
- `cancelled { query_id, completed, total }`
- `failed { query_id, code, message, retryable }`

`result` 是 `success { stock, summary }` 或 `failure { stock, stage, code, message }`。所有可缺失数值和日期均序列化为 `null`，不使用零或空字符串代替。`CommandError` 与失败事件均包含稳定的机器可读 `code` 和可展示 `message`。

前端为每次查询生成唯一查询 ID。启动新查询前请求取消旧 ID；卸载页面时取消当前查询。后端维护可取消标记，在每次网络请求前后检查；取消后停止派发新任务并发送一次 `cancelled`。由于已经发出的网络请求不保证可中断，前端仍必须按查询 ID 丢弃过期事件。

### Rust 服务

新增独立 `dividend_query` 服务。复用现有东方财富 HTTP 获取能力和经过测试的分红/行情解析逻辑，但不依赖现有固定选股策略、央企分类或 BOLL 计算。

服务内部边界：

- `industry/universe`：构造并解析行业及成分股请求。
- `dividend`：获取分红历史并统一状态和每股口径。
- `quote`：批量获取当前行情。
- `orchestration`：控制并发、取消、进度、聚合结果和记录部分失败。

现有 `screener_source_eastmoney_market.rs` 中的 URL 构造和 JSON 解析是可复用起点。共享层只负责第三方原始字段解析和无损 DTO；本页面的年度选择、状态汇总、去重和股息率计算放在独立领域层。扩展共享模型时必须保留现有 `NormalizedDividend` 行为，并用现有选股固定样本做回归测试，不能让新字段改变当前选股结果。

行业查询最多同时进行 6 个单股分红请求。单次请求超时 10 秒；仅网络错误、HTTP 429 和 5xx 重试 1 次，重试前等待 500ms，解析错误和 4xx 不重试。行情按最多 100 只股票分块批量请求；批次失败后对该批重试 1 次，仍失败则对应股票保留分红摘要，行情和股息率置空。股票在分红阶段得到成功或最终失败后计入 `completed`，每只股票只增加一次进度。

## 数据口径

### 分红记录

每条记录保留以下原始或可追溯字段：

- 报告期。
- 原始方案文本。
- 第三方返回的实施进度。
- 每 10 股现金金额和归一化后的每股现金金额。
- 股权登记日和除息日。
- 公告日期、公告标识或公告入口信息。

统一状态包含：`proposal`、`approved`、`implemented`、`cancelled` 和 `unknown`。界面分别显示“预案”“已通过”“已实施”“已取消/终止”“状态未知”。

同一第三方记录 ID 的多次返回只保留公告时间最新的一条。没有稳定记录 ID 时，使用股票、报告期、每 10 股现金金额和除息日组成替代键；替代键相同则保留公告时间最新的一条。状态为取消、终止、否决或不分配的修订记录归一化为 `cancelled`，金额不得进入任何合计。无法可靠关联的记录不做猜测性合并，保留并标记数据质量提示。

### 最近完整年度

“最近完整年度”指查询基准日所在年度之前、存在至少一条非取消现金分红披露的最近报告期年度。报告期以第三方返回的 `REPORT_DATE` 年份归属，可包含该年度的季度、中期和年度报告分红；同一报告期年度内的多次现金分红在去重后合计。该定义表示“已结束年度的披露合计”，不推断没有记录的年度为零，也不要求年度报告已经披露。跨年实施仍归入其报告期年度，而近 12 个月口径按实际除息日统计。

该口径同时返回：

- 该年度已实施每股现金金额。
- 该年度待实施每股现金金额。
- 该年度全部披露现金方案金额。
- 以全部有效披露现金方案金额除以当前价计算的披露口径股息率。
- 以已实施金额除以当前价计算的已实施口径股息率。

状态归属固定如下：

| 统一状态 | 已实施金额 | 待实施金额 | 全部有效披露金额 |
|---|---:|---:|---:|
| `implemented` | 计入 | 不计入 | 计入 |
| `proposal` | 不计入 | 计入 | 计入 |
| `approved` | 不计入 | 计入 | 计入 |
| `cancelled` | 不计入 | 不计入 | 不计入 |
| `unknown` | 不计入 | 不计入 | 不计入 |

列表主列默认展示全部有效披露口径，并同时展示已实施和待实施金额，避免把待实施金额误认为已到账。没有符合定义的报告期年度时，各年度字段为 `null`，不显示为零。

### 近 12 个月

后端在查询开始时按 `Asia/Shanghai` 捕获一次查询基准日期和时间。以该日期向前回退 12 个日历月形成闭区间，按除息日纳入记录，仅统计状态为“已实施”的现金分红。已实施但除息日缺失的记录保留在历史详情并显示数据质量提示，但不计入近 12 个月。整个查询批次使用同一基准日期，避免跨日边界不一致。

### 股息率

股息率等于对应口径的每股现金金额除以当前价。“当前价”只接受东方财富返回的最新成交价；停牌或无成交导致最新价缺失时，不使用前收价回退。当前价不存在或不为正数时股息率返回空值，界面显示 `--`。

后端在分红查询开始后立即发起行情批次请求，保存东方财富行情时间；如果接口没有单独行情时间，则使用响应接收时间并标记为 `received_at`。同一查询结果携带统一的查询基准时间、各行情批次观察时间和分红获取时间。股价可能在批次间变化，界面以每行行情时间解释，不宣称结果为同一市场快照。

所有股息率必须带口径标签，不直接复用第三方接口中语义可能不同的股息率字段。

## 数据来源与真实性提示

页面明确标注“分红与行情数据来源：东方财富公开数据接口”，并分别展示行情观察时间和分红数据获取时间。

东方财富属于第三方聚合源，不表述为交易所官方数据。公告入口用于人工追溯；若入口仅为检索页，界面必须明确标注，不能显示为“公告原文”。

## 错误处理

- 行业列表失败：查询控件显示错误和重试操作。
- 股票搜索失败：保留输入内容并显示局部错误。
- 行业成分股失败：终止该次查询并显示页面级错误。
- 行情失败：仍展示分红数据，现价和股息率显示 `--`。
- 单股分红失败：保留该股票及失败原因，其他股票继续完成。
- 返回字段缺失或格式异常：解析器返回明确错误，不静默转换为零。
- 第三方限流或超时：使用规定的受限并发、超时和有限次数重试；不无限重试。
- 全部单股分红请求失败：查询以 `finished` 结束并保留全部失败行，页面显示批量失败警告和重试，不误报为成分股获取失败。
- 行情全部失败：查询仍以 `finished` 结束并展示分红摘要，页面提示股息率暂不可计算。
- 行业列表、行业成分股获取或事件流在产生结果前中断：发送或呈现页面级 `failed`。
- 用户取消：呈现取消状态，不作为错误；已完成结果不再追加，旧查询事件不能改变新查询。

## 测试

### Rust 单元测试

- 行业列表和成分股 JSON 解析。
- 分红方案文本、金额、日期、公告字段和状态归一化。
- 修订、重复、取消和终止方案的去重与金额排除。
- 最近完整年度选择及已实施/待实施拆分。
- 近 12 个月的月历边界、闰年和除息日统计。
- 当前价缺失或为零时不计算股息率。
- 批量查询中部分失败仍返回其他结果。
- 全部单股失败与行情部分/全部失败的最终状态。
- 并发限制和有限重试行为。
- 查询取消及取消后不再派发任务。
- Rust DTO 与前端联合类型的固定样本序列化合同。
- 共享解析器扩展不改变现有选股固定样本结果。

### 前端测试

- 未选择条件时不能查询。
- 查询模式切换清理不适用条件。
- 两种口径切换改变重点列和默认排序。
- 股息率区间、状态筛选和排序。
- 进度、空状态、整体错误和单股错误展示。
- 新查询取消旧查询，并忽略查询 ID 不匹配的过期事件。
- 详情抽屉展示历年记录及正确的公告入口标签。

常规自动化测试使用固定 JSON 样本和模拟 Tauri 响应，不依赖实时第三方网络。可另设显式执行的 live API 测试用于人工验证接口兼容性。

## 验收标准

- 用户可选择任一东方财富行业并主动查询其 A 股成分股分红摘要。
- 用户可通过代码或名称找到 A 股并查看历年分红详情。
- 表格同时展示最近完整年度和近 12 个月两种股息率，定义与实施状态清晰。
- 单只股票请求失败不会中断整批行业查询。
- 所有数据都能看到来源和采集时间，公告原文与公告检索入口不会混淆。
- 页面首次打开不进行全 A 股分红请求，也不建立持久化缓存。
